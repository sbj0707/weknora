# Elasticsearch 8 knowledge index moves

`Elasticsearch8Store.moveKnowledgeIndices` performs the actual ES8 `_update_by_query?refresh=true` request. It filters the exact source KB and document using mapping-dependent ID field names, sets the target KB and clears the KB-scoped tag. Chunk IDs, dimension and knowledge type are intentionally unused, as in Go. Disabled rows and all source types are included. Physical document IDs, source/chunk/document IDs, full content, vectors and enabled flags are retained. Empty and quoted scope strings are transmitted without trimming. This is an index operation; admission and the document/chunk transfer remain the move service's responsibility.

Success requires present, nonnegative `total` equal to `updated`, no timeout, no version conflicts and an empty failure list. Zero/zero is a valid repeated move. The response decoder follows the actual pinned Go ES8 typed client's first-JSON-value behavior, duplicate/null/case-folded struct fields, numeric types and custom `Retries`, `BulkIndexByScrollFailure` and `ErrorCause` unmarshallers. HTTP status 299 already takes the error path. Error responses retain the Go client's status/type/reason format, including its raw string and `strconv.Unquote` behavior. Retryable 502/503/504 responses and failures before response headers receive at most three retries; decoding or body-read failures do not trigger transport retries. Caller cancellation/deadline covers the HTTP operation and its response stream. The first successful response verifies `X-Elastic-Product` once, retaining that verification across constructor and move calls. Redirect responses are decoded directly without following Location, matching the Go RoundTripper. No separate 30-second whole-request timeout is imposed on long moves.

`GoUploadJson` now accepts an optional custom decoder. Existing callers use the original constructor; custom callbacks receive the original string so JSON raw messages are not regenerated or reordered. An unwrapped custom type error receives the enclosing Go struct-field context. Float32 decoding uses direct 32-bit parsing and rejects overflow, rather than parsing all floating-point types as float64.

The actual Go fixture `src/test/fixtures/elasticsearch_index_move_fixture.go` calls the production repository and pinned typed client through a loopback HTTP server. It exports 252 response/request/retry cases and two stalled-HTTP cancellation/deadline cases. The Java tests replay complete HTTP method/path/query/body and attempt counts, exact returned errors, the reflected response schema and cancellation before response release. The fixture uses the client's default retry settings, rather than disabling retries for tests.

The separate physical fixture runs the production Go repository against an owned ES 8.14.0. Twenty-two cases cover keyword and text+keyword mappings, exact scope, unrelated KB/document rows, enabled/disabled rows, already-target rows, ignored optional arguments, empty/quoted strings, same-KB moves and repeated invocation. Java compares three full physical snapshots and six source/target/third-KB vector/keyword retrieval samples per case (66 snapshots, 396 retrieval samples). Automatic ES IDs differ across independent seeds, so each engine must retain its own complete ID map; full `_source` rows and vectors are compared across engines. JSON numbers compare by decimal value (`1` equals `1.0`); string/boolean/array content is retained. Retrieval source-ID sets are sorted, without asserting unspecified tie order or scores. Existing physical retrieval/deletion parity is rerun on the same owned engine. This does not prove every dimension, ES version, mapping, transport failure or concurrent-cluster behavior.

Reproduce from the repository root:

```sh
go run backend-java/src/test/fixtures/elasticsearch_index_move_fixture.go /tmp/go-es8-move.json
# The checked-in resource is the exact exported Go JSON, not a Java-generated expectation.
mvn -f backend-java/pom.xml -Dtest=Elasticsearch8MoveGoParityTest,Elasticsearch8MoveContextGoParityTest test
python3 backend-java/scripts/elasticsearch-index-move-parity.py
```

The physical runner creates a uniquely named loopback-only container and indices, records Go/Java/engine logs, and stops only its own container. It also reruns the preexisting two mapping groups of physical ES retrieval/deletion parity.

This increment does not add a public route or worker. Binding resolution and production move effects still need wiring; the document processing resolver still rejects bound external vector stores. Go ES7, OpenSearch, Milvus, Weaviate, Qdrant, Tencent VectorDB and Doris moves remain unported. Graph/image/file cleanup, complete Wiki reconciliation, retained downstream queue admission, Redis progress, public move/progress endpoints and the `knowledge:move` worker remain required. Full Go migration and deployment cutover are incomplete. Current test/build evidence and input hashes belong in `migration/elasticsearch-index-move-checkpoint-2026-10-16.json`; historical SQL/execution checkpoints do not validate later changes.
