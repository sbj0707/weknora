# Tenant settings migration

Native endpoints with scoped SQLite validation (full Go parity remains in progress):

- GET `/api/v1/tenants`: current workspace only, not a membership or cross-workspace list.
- GET `/api/v1/tenants/{id}`: Viewer, active-path match or explicitly enabled cross-workspace superuser.
- PUT `/api/v1/tenants/{id}`: Owner, name/description whitelist; omitted/null fields preserve values.
- GET `/api/v1/tenants/all`, GET `/api/v1/tenants/search`: both cluster cross-workspace flag and user attribute; every row uses Viewer redaction even for an Owner caller.
- GET/PUT `/api/v1/tenants/kv/retrieval-config`, GET/PUT `/api/v1/tenants/kv/memory-config`: Viewer reads, Admin writes; tenant API keys require `manage_tenant_settings` or full access.

Platform keys/external API principals remain rejected by native authentication. Tenant keys cannot call detail, metadata update, or cross-workspace catalogs: the Go route declares these `PlatformOnly` before its full-access bypass. Scoped settings keys cannot reveal integration secrets through current-workspace DTOs, because Go represents them with Viewer role. KB allow-lists do not constrain tenant settings.

JSON configuration replaces the entire typed configuration, rather than merging arbitrary fields. Unknown fields are dropped; null scalar fields bind to Go zero values, null pointer booleans stay null. Memory validation precedes default normalization; embedding model IDs use a 64-byte UTF-8 bound, instructions a 1000-Unicode-code-point bound. Zero delay/interval means 90/300 seconds; positive delay below 5 is clamped to 5. Retrieval RRF integers retain signed 64-bit range and optional zero fields are omitted. Memory GET normalizes a copy; ordinary TenantResponse serializes the stored typed memory config without that GET normalization.

A real Go/GORM fixture confirms metadata `description=""` is returned as empty but skipped during `Updates(struct)`, leaving the persisted description unchanged. This behavior is deliberately preserved. Mutable SQL is limited to the selected columns; privileged quota/status/business/credentials/config/default storage/vector bindings cannot be changed through metadata PUT. Preserving untouched storage columns avoids accidental secret rewrites or lost concurrent storage updates. Go nevertheless reloads and scans all tenant rows during storage bucket uniqueness validation whenever storage config is non-nil. That dependency, including unrelated-row scan failures, is not yet reproduced by these Java settings writes; unchanged bucket values alone do not prove complete service parity.

Writes use a transaction and acquire the tenant row through a no-op update (PostgreSQL row lock / SQLite write lock), then recheck the actor's live membership role. This is stronger than Go's request-start role snapshot. Failed writes roll back. Go tenant metadata/config writes have no business audit callback; role-denial audits are best-effort with the Go route template, required role, raw path and one-minute deduplication. JSON SQL binding shares the tested PostgreSQL JSONB / SQLite text strategy used by native authentication.

Dependency audit: memory-config updates only normalize and save tenant configuration; they do not create a KB, model, or task. Its later memory extraction/retrieval execution is outside these configuration routes. Chat-history changes can create a hidden managed KB, and remain on Go. Storage/web-search KV changes need credential-preserving merges, URL/provider validation, storage bucket uniqueness, and the storage resolver SPI; they remain on Go. Parser-engine KV has now been ported as described below; shared tenant-service storage validation remains pending. Tenant create/delete, invitations, audit feed, API-principal configuration and default storage/vector binding are not counted as implemented here.

Fixtures: `tenant_golden.go` runs actual Go types and SQLite GORM; `tenant-golden.json` records typed/default memory configurations, retrieval zero/RRF fields, and description zero-skip behavior. `TenantHttpIntegrationTest` uses an isolated real SQLite database with repository migrations `000000`, `000004`, `000007`, never a user database.

Validation: `mvn -q -Dtest=TenantHttpIntegrationTest,SecurityCompatibilityTest test` passed 30 tests (10 tenant, 20 security), zero failures/errors. PostgreSQL-specific JSONB SQL binding is shared with authentication; this phase ran real SQLite, not a live PostgreSQL instance.

## Parser-engine configuration KV checkpoint

Exact GET/PUT `/api/v1/tenants/kv/parser-engine-config` now have a native controller/service and exact bridge selection. Reads require integration Admin access for JWT users, including a system-admin user with a Viewer membership; settings-capable tenant API keys can read and write. PUT role denial precedes malformed-body binding and audits use the generic `/api/v1/tenants/kv/:key` template. Other KV keys retain their existing implementation owner.

The real Go handler, tenant service and production-schema SQLite generator `src/test/fixtures/parser_config_kv_fixture.go` provides 1,092 HTTP response/persisted JSON/timestamp cases. They cover SQL NULL versus BLOB versus TEXT scans, typed first-value request parsing, folded and duplicate fields, reused slice backing, explicit false pointer booleans, three secret-preserving merges, omitted/null versus empty rules, and endpoint SSRF validation order. Java stores parser config as a SQLite BLOB and masks only the response; Go stores these parser secrets as plaintext JSON, separately from encrypted cloud credentials. Raw JSON bytes and JDBC fault messages are not claimed byte-identical.

Four `TenantParserConfigHttpTest` methods also cover the real authentication filter, API capabilities, foreign-tenant isolation, denied-role audit deduplication, rollback and live role recheck. The 1,092 oracle scenes are iterations inside a single method, not 1,092 additional JUnit tests. The isolated 10-class settings/serialization regression passed 1,259 tests with zero failures/errors/skips (`/tmp/weknora-java-parser-kv-checkpoint-fixed.log`). Actual PostgreSQL and Go's all-tenant storage validation dependency remain pending; the generic two KV inventory routes stay `in_progress`.
