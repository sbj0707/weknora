# Native graph extraction batch

The first batch replaces the `chunk:extract` worker and document postprocess graph dispatch with native Java, and makes document index-status/chunk-details report actual Neo4j counts and rows. The subsequent batch implements the native graph repository's search/delete methods and document-worker cleanup of old graph data. Chat/RAG entity-extraction/search integration, public reparse/delete APIs and Wiki tasks remain separate migration work.

## Production behavior

- Effective KB/document configuration, text/OCR chunk selection, ordinal/attempt payload omission, queue `graph`, three retries and 30-minute timeout follow captured production Go dispatch. Graph tasks occupy the same parent pending counter as summary and question batches; AutoTag occupies no slot and is enqueued first, as in Go.
- The existing Go prompt description is versioned in `graph-extraction-prompt.json`. Effective extraction examples, custom instructions, temperature `.3`, max tokens `8192` and thinking=false are retained. The formatter handles dictionaries, arrays, fenced/truncated/prose JSON, ignored unsupported groups, duplicate entities and unknown endpoints. Duplicate first-node attributes are deliberately preserved because the current Go formatter discards the later merged object.
- Actual Neo4j/APOC merge uses Go's two namespace labels, `{name,kg}` identity, attributes-on-create, chunk union and dynamic relationship types. Nodes and relationships share one managed graph transaction. Counts and public chunk detail are real database queries; disabled/unavailable stores do not manufacture graph evidence from spans.
- SQL owner/document/KB/chunk binding, attempt, content revision, lease and task cancellation are checked before model work and again before publication. The same guard runs inside the real Neo4j transaction; a failure after node insertion rolls back the whole graph transaction.
- SQL terminal receipts make duplicate terminal handling idempotent. Apply `migration/sql/java-tasks.sql` when creating a Java task schema, or explicitly apply `migration/sql/java-graph-drains-upgrade.sql` to an existing task database. Constructors perform no DDL.

## Go baseline safety corrections

Before changing Go, a real production worker oracle with HTTP, SQLite, Asynq and isolated Neo4j captured unsafe behavior: foreign document/KB chunks were sent to the model and persisted; cancellation, a newer attempt and content revision changes during Chat could publish stale graph data and drain a successor counter; orphan documents could create traces. The historical artifact remains `/tmp/weknora-go-graph-unsafe.json`.

`extract.go` now validates the owned document before creating a span, validates complete chunk and KB ownership, and rechecks binding/cancellation/attempt/revision after Chat including Chat error paths. Invalid binding is rejected without draining another document's counter; superseded work cannot drain successor slots. The safe 41-case artifact comes from running the modified real Go service, not by editing expected outcomes.

## Driver and infrastructure

[Official Neo4j Java driver documentation](https://neo4j.com/docs/java-manual/current/install/) identifies driver 6.1.0, Java 17+, and Neo4j 4.4/5/2025/2026 compatibility. Production uses Java 21 and driver 6.1.0. Spring Boot 3.5's built-in driver factory calls a removed driver method; the unconditional project graph configuration excludes that auto-configuration and owns its independent driver. `NEO4J_ENABLE=false` creates no hidden driver, including with document processing disabled. `NEO4J_ENABLE=true` checks connectivity and actual `apoc.version()` on startup.

Tests used an independent disposable `neo4j:latest` image reporting Neo4j **2026.09.0**, with actual local APOC **2026.09.0**. Its Bolt endpoint is `127.0.0.1:53505`; it has no development volumes. Live tests require an explicitly provided isolated URI and fail if Neo4j/APOC is absent. They do not skip or substitute an in-memory graph. Only this isolated test instance's oracle namespaces are reset.

## Remaining limits and differences

- Native fanout is one SQL transaction (counter and durable child jobs); Go enqueues children nonatomically and compensates for enqueue shortfalls. Existing document chunk/index publication is also atomic; Go publishes chunks before embedding. Neither difference is hidden by the oracle.
- Neo4j publication and the SQL completion receipt are separate transactions, without distributed two-phase commit. A process failure after graph commit but before SQL receipt can replay the idempotent graph merge. Idempotent SQL receipts are stronger than Go's counter decrement, which has no task-ID receipt.
- Call deadlines become actual Neo4j transaction timeouts and lease/cancel guards run before commit. A blocking wire query may wait until its server timeout; this batch does not claim immediate network rollback on cancellation.
- Non-string numeric entities/attributes use Go binary64 semantics validated by the additional 521 real formatter samples. Configured prompt description formatting covers the actual shipped `%s`/`%%` template; arbitrary exotic printf verbs/flags in a future replacement template have not been validated.
- Repository `SearchNode` and document-scoped `DelGraph` are native; chat/RAG plugins are not yet wired to this repository search. The native document worker cleans old graph data during initial/replacement processing, but existing public reparse/document-delete/KB-delete routes still require their own migration and cleanup hooks. Relation records intentionally have no chunk provenance beyond endpoint chunks, matching the current Go schema.

## Subsequent search, cleanup and prompt batch

These changes postdate the immutable 5657-test/packaged checkpoint above. Their evidence is recorded separately.

- A real Go worker capture demonstrated that percent signs in configured custom instructions were interpreted as printf directives when tags were supplied. The historical 42-case artifact is `/tmp/weknora-go-graph-before-percent.json` (and `.log`). Go now escapes user-supplied percent signs before composing the prompt; Java applies the same rule. The new production Go fixture `/tmp/weknora-go-graph-after-percent.json` supplies all **42** strict worker cases, including literal `10%`, `%s`, `%q` and `%%`; the system template continues formatting its own placeholders.
- Actual Neo4j search showed a label-normalization collision: hyphens and underscores produce the same label, so two historical/custom document IDs can share labels. The old Go search returned foreign document chunks/attributes despite a document-scoped namespace. `/tmp/weknora-go-graph-search-before-scope.json` preserves that result. Both production implementations now require the exact document `kg` on seeds and neighbors when a document ID is provided. KB-wide search intentionally spans documents after the caller grants the KB; the repository itself is not a tenant authorization layer.
- Actual Go deletion with an owned-to-foreign relationship returned success while leaving owned nodes behind: the old APOC action used `DELETE n` and rejected nodes with remaining edges. `/tmp/weknora-go-graph-delete-before-detach.json` preserves that evidence. The Go baseline action is now `DETACH DELETE n`; the native implementation uses the same owned labels/`kg` predicates and retains foreign nodes/relationships. Detaching an owned node removes its incident cross-document edge as expected.
- Same-name KB-wide seeds had an unspecified tie order. A strict replay failed because Go selected the owner's first `Alice` attributes/chunks while the Java query selected the other document's `Alice`. The failed log is `/tmp/weknora-java-graph-repository-final-test.log`, and `/tmp/weknora-go-graph-repository-before-order.json` preserves the earlier Go result. Production Go and Java queries now order seeds additionally by `n.kg`, and expanded rows by `n.kg,m.name,m.kg,type(r)`. The first-node semantics are preserved. Tests compare complete node/relationship arrays without sorting expected or actual data.
- `GraphRepositoryGoParityIT` and `GraphRepositoryCapsGoParityIT` passed **3** live Neo4j/APOC tests against newly captured ordered production Go fixtures: `/tmp/weknora-java-graph-repository-order-test.log`. The 423-node fixture tests 200 seed selection, exact-name priority and isolated-seed exclusion; the 2006-node fixture tests 2000 rows and deletion over multiple 1000-node batches. Result arrays contain respectively **400 nodes/200 relations** and **2001 nodes/2000 relations**, and both document graphs are empty after deletion.
- A valid relation-only `GraphData` creates endpoints without attributes/chunks. Real Go `SearchNode` panicked on a nil-to-list assertion; `/tmp/weknora-go-graph-properties-before.json` and `.log` retain that failure. Go now treats legitimately absent lists as empty while preserving its non-list error semantics. Actual stored integer/float/boolean arrays also exposed Java's former string-only conversion. Native search now retains Go formatting: integers use their full signed 64-bit decimal, floating values use the verified binary64 formatter, and booleans use lowercase literals. The **5** real Go property fixtures include relation-only, nil properties and typed arrays; floating fixtures carry authoritative Go raw bits to preserve negative zero when reconstructing storage, and include the smallest subnormal and largest finite double. They are not decimal-rounded JSON substitutions. The expected returned strings include `-0`, `5e-324` and `1.7976931348623157e+308`.
- Production document processing calls graph cleanup after capturing the current replacement and resolving the embedding model, before embedding/publication. Owner/source/attempt and the actual task lease are rechecked inside the graph transaction without holding the SQL connection during graph I/O. Ordinary graph-store errors remain best effort, matching Go's document path; cancellation/lease/source failures propagate. Existing native SQL chunk/index publication remains atomic after embedding, unlike Go's earlier SQL cleanup and chunk publication.
- `GraphExtractionPipelineHttpIntegrationIT` now has **10** actual Spring/live Neo4j cases. The additions confirm old graph removal before embedding and preservation of the old graph if a guard fails after graph deletion inside the transaction. The **42 worker + 521 number formatter + 10 pipeline = 573** focused cases passed without failure/error/skip: `/tmp/weknora-java-graph-prompt-cleanup-final-test.log`.
- Native graph deletion batches run in one managed graph transaction, so a late failed guard rolls back previous batches. Go uses APOC periodic transactions and can commit earlier batches. This is a deliberate native atomicity difference, not claimed identical partial-failure behavior.

The final combined command passed **11 classes / 628 tests / zero failures/errors/skips**: `/tmp/weknora-java-graph-search-properties-final-test.log`. It includes 42 actual Go workers, 521 numeric formatter cases, 18 Go fanout cases, 10 live pipeline cases, 8 live repository cases, 2 schema cases, 1 disabled-startup case and existing Question fanout/pipeline 17/9.
