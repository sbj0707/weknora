# Chunk tombstones and revision reads

Native processing mode now includes `DELETE /api/v1/chunks/:knowledge_id/:id`, `DELETE /api/v1/chunks/:knowledge_id`, and `GET /api/v1/chunks/:knowledge_id/:id/revisions`. They do not expand the Go compatibility bridge whitelist. These routes remain `in_progress`; full chunk editing/reversion/questions and full service cutover are separate work.

The actual production Go handler, service, repositories, ownership/KB/API middleware and SQLite SQL produced 117 cases. The checked-in oracle is `src/test/resources/go-chunk-delete-http.json`; regenerate with `go run -tags sqlite_fts5 backend-java/src/test/fixtures/chunk_delete_http_fixture.go output.json` from the repository root. The fixture injects identities and records both the input role and the effective role obtained from production Go `TenantRoleFromContext`; it does not test Go authentication. Invalid persisted membership handling remains a wider authentication boundary.

Deletes require ingest/full API capability, own-KB creator or workspace Admin, and shared Editor access. Creator Viewer is permitted. Read revisions require retrieve/full capability, Viewer and the parent KB read grant, including supported shared Agent grants. Full-access API keys still obey their KB allow-list. Guard lookup uses the raw path document ID before handler sanitization. Each delete revalidates the current document owner, KB and unfinished move metadata; single delete also validates the chunk/document/KB relationship. A transactional native write makes its validation and tombstone atomic; this is not proof of every Go/Java concurrency race.

Direct deletion only soft-deletes chunk rows. Single deletion retains child rows. Bulk follows Go's tenant/document predicate across chunk types, statuses and even inconsistent stored KB IDs; foreign-tenant and other-document chunks are retained. Neither operation deletes physical indexes, graph, immutable revisions, source resources, storage quota or queues an index/document cleanup task. These semantics are intentionally distinct from public document deletion.

Revision reads verify the active tenant-bound chunk and path document relationship, then return the complete immutable revision DTO ordered by revision descending. They do not apply a write/moving guard. Invalid persisted document/chunk KB combinations are matched to the actual Go read behavior, without claiming additional ownership hardening.

Transfer metadata decoding retains Go outer case-sensitive map keys, inner case folding, duplicate/null behavior and the anonymous typed error strings exercised by the oracle. Single/bulk service errors are wrapped as Go's internal error strings. PostgreSQL errors use the actual driver's server severity/message/SQLSTATE, without locale-dependent Java position/PLpgSQL context suffixes. PostgreSQL is a compile dependency so this diagnostic uses typed driver fields; its version and packaged dependency are unchanged.
