# Document list deletion

Native `knowledge:list_delete` and the public document-tag `force`/`content_only` producer are implemented under the existing processing switch. This batch is included in the immutable 6,371-test jar. Go bridge ownership has not changed. The worker receives an admitted owner/KB/document snapshot; the initiator supplies audit identity, never authorization.

`knowledge_list_delete_fixture.go` runs the actual Go worker, domain services, SQL repositories, real SQLite vec/FTS engine, local file service and resource catalog. Its 36 scenes cover success, idempotent missing/tombstone references, duplicates, legacy scope reconstruction/ambiguity, malformed typed payloads, foreign/changed ownership, same-owner wrong KB, moving documents, missing/foreign/wrong-type embedding models, empty models, no engines, failed index/graph/file effects, underflow clamping and initiating caller audit. Two real resource-catalog cases preserve an image still referenced by another document and remove its last owner claim before deleting bytes. Resource handles generated by Go are replayed as the same persisted reference in Java.

The native replay compares complete document/chunk state, surviving source indexes, actual metadata/vec/FTS row counts, file calls/bytes, quota, tag relations, resource state/bindings and business audit fields. It compares worker failure and SkipRetry decisions; dependency-specific error wording is deliberately not a byte-level parity claim. Native audit `task_id` is separately asserted against the actual SQL job ID; a directly invoked Go fixture has no Asynq task-context ID. Generated relation timestamps are outside this cleanup projection. Earlier oracle attempts exposed missing required source/timestamp/schema seeds, which were fixed in the fixture without weakening production checkpoints.

`WEKNORA_TAG_DOCUMENT_PARITY=true` selects 12 additional public Go tag scenes in `tag_crud_fixture.go`. These execute actual handler/permission/SQL/Asynq admission. Java compares complete HTTP envelopes, business audit fields and queue payloads/options, including force removal vs content retention, queue failure retaining the tag, missing document references falling back to chunk cleanup, shared permissions and API-key identity. Four attempts, low/maintenance queue and a two-hour timeout match Go's three retries. All original 76 tag scenes remain in their separate regression oracle.

Cleanup marks documents deleting before its index/chunk/graph branches. A failed branch retains that checkpoint and leaves file/accounting finalization pending, matching Go's retry path. Successful cleanup removes document rows before physical files, then adjusts quota and requests a best-effort profile refresh. File, image-release, quota and audit failures are nonfatal; an unreadable resource claim retains its image. Pending/processing documents cancel the same native document task set. Models used for cleanup require dimensions, without inference or an embedding-type restriction.

Native SQL mutations additionally fence lease/attempt/deadline/cancellation, current KB owner, document binding, parse state and update checkpoint. PostgreSQL row locks and stronger transactional fences are intentional protections, and do not imply parity for Go's partially committed multi-document failures. Unsupported Wiki cleanup, bound/external vector engines and cloud storage fail before destructive effects; their full Go lifecycle remains unported. Multi-model/dimension corruption, restart/redelivery windows, concurrent sharing/moves, all public delete/batch-delete endpoints and complete cutover remain pending. No route or task is marked verified.
