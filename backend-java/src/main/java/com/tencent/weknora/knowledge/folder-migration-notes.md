# Native knowledge folders

Native processing mode includes `GET /api/v1/knowledge-bases/:id/knowledge/folders`, `PUT /api/v1/knowledge-bases/:id/knowledge/folders`, and `POST /api/v1/knowledge/folder`. These three routes remain `in_progress`; the bridge whitelist is unchanged.

The checked-in 151-case oracle comes from actual Go handlers, business services, repositories, SQLite, API-key/KB/role/ownership middleware and denied-role audits. Regenerate from the repository root with `go run -tags sqlite_fts5 backend-java/src/test/fixtures/folder_http_fixture.go output.json`. Identities are injected; this is not evidence of Go authentication itself. Native production JWT/API-key filters are covered separately. The original HTTP/SQL export `/tmp/weknora-go-folder-http-before.json` was retained and compared unchanged when adding audit projections.

Trees exclude deleted and mid-deletion documents, scope by the resolved owner tenant and KB, normalize stored paths, materialize missing ancestors, accumulate direct and descendant counts, and omit empty children. Empty `folders` is an array. Go simple Unicode lowercase and UTF-8 byte ordering are used for labels. The corpus does not establish every case-folded equal-name ordering in unordered SQL groups.

Rename checks ingest/full capability, own-KB creator or workspace Admin and shared Editor before JSON binding. Creator Viewer may rename. The binder preserves Gin's first JSON value, typed duplicate/null behavior, field folding and exact required-field diagnostics. Rename validates the destination label, rejects root/self-descendant destinations, treats equal paths as a no-op, merges existing destinations, and rewrites only exact or escaped LIKE subtree matches in a transaction. It retains Go's inclusion of mid-deletion and moving rows in subtree renames; these are not batch-move semantics. Malformed persisted raw paths do not silently become additional SQL matches merely because the tree displays their normalized path.

Batch move checks ingest/full capability and Contributor before binding, trims and deduplicates document IDs in caller order (maximum 200), resolves a single KB write grant and checks handler ownership. This handler ownership refusal does not emit a middleware role-denial audit. Every requested document must exist in the owner tenant and target KB before target label validation. The service then rejects unfinished moves before updating all rows. Empty destination means the KB root. Native transactions revalidate document/KB owner identity; full concurrent share revocation/relocation/move equivalence remains pending.

Path normalization uses the existing import helper: separator conversion, dot/empty-segment removal, trailing dot/space stripping, maximum 16 levels, 128 UTF-8 bytes per segment without splitting a code point, and 1024-byte whole-path budget. Invalid target controls/XSS produce Go validation code 1010. Re-filing changes only `folder_path` and `updated_at`; chunks, physical indexes, graph/resources, source bytes, storage quota and task queues are retained.
