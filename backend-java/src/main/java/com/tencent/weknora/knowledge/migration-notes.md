# Knowledge ingestion configuration

KnowledgeProcessConfig ports the production Go ResolveProcessConfig merge used by knowledge ingestion. It keeps KB defaults, distinguishes nil overrides from an empty override object, honors the full chunking snapshot's false parent-child flag, ignores zero numeric/empty collection replacements as Go does, applies explicit top-level parser rules last, preserves VLM description language/custom instructions on empty replacements, replaces ASR fields, inherits question guidance and gates graph fan-out on extract.enabled. It uses a schema generated from the real Go types for nested defaults, pointer omission and serialized fields. It retains Go's conservative OCR action policy and per-action overrides. Root docreader.ParserConfiguration handles parser engine selection and workspace/parser request overrides.

The shared file import gate applies the supported-extension set, video rejection and VLM/ASR requirements. The legacy ValidateProcessOverrides image gate is case-sensitive while its audio gate is case-insensitive; the default import gate normalizes its extension first. This observable Go distinction is preserved. Prompt instruction caps count Unicode code points, with the same 4000-character field messages. If multiple fields exceed the cap, Go's map iteration can select any offending field; Java picks a stable field order. KnowledgeUploadForms now uses a separate Go-compatible typed JSON decoder, preserving duplicate-field error ordering, case-insensitive struct field matching, pointer nulls and metadata string-only typing.

KnowledgeImportNames ports SplitKnowledgeRelativePath, NormalizeKnowledgeFolderPath, ValidateInput and SanitizeForLog. Folder segments use a 128-byte UTF-8 budget, not a Java-character count; paths cap at 16 segments and 1024 bytes without partial Unicode characters. Display folder paths never determine physical storage location. Validation retains the production Go RE2 patterns and control-character/UTF-8 rules. KnowledgeMultipartUpload preserves Go Unix header basename normalization before domain logic; its raw streaming parser runs only after the KB write grant.

KnowledgeRepository and KnowledgeFileUpload now port the internal file-upload lifecycle over the existing Go knowledge/tag tables and native Java FileStore contracts. The authorized owner tenant is required for KB/knowledge reads, duplicate checks, creation and tags. Files are hashed before duplicate checks; same bytes are distinct across file types and, for GitLab/Confluence, datasource/external identities. Failed/deleting rows and soft-deleted rows do not block uploads. Custom paths affect display/folder/parser identity while physical storage retains the original multipart filename. A database create failure compensates the saved physical file/resource; tag validation occurs after storage/database persistence as in Go. Tag loading after binding is best effort. Primary enqueue failure returns the durable knowledge marked failed; a separate spreadsheet summary enqueue failure leaves the document pending.

The Enqueuer contract explicitly requires durable acceptance, queue selection, retries and task timeout. Document tasks use queue default, three retries after the initial attempt, and a configurable two-hour default timeout; datatable summaries use queue summary, three retries, and 30 minutes. The production KnowledgeFileTaskEnqueuer now preserves these options through the durable native TaskRepository schema and TaskWorker. Producers use fresh job IDs to retain Go enqueue behavior. Native processing beans are opt-in; existing bridge startup remains unchanged.

Native multipart HTTP/controller and worker foundations are now implemented under explicit flags: `weknora.tasks.enabled=true`, `weknora.knowledge.processing.enabled=true` and separately `weknora.knowledge.upload.enabled=true`. Upload is disabled by default, and the global Go bridge route selector and AuthFilter upload API-key policy remain unchanged. Controlled native smoke tests must disable the bridge. No upload route is counted fully migrated on this foundation alone.

KnowledgeUploadController calls the real KnowledgeBaseWriteAuthorization before reading any multipart bytes. Shared uploads use only the grant's KB owner tenant for knowledge/resource/task/quota operations while retaining the original foreign caller for best-effort owner-scoped `knowledge.created` audit. The handler validates metadata/process JSON/booleans/tags/custom names and the `.json` content gate, then delegates to the original native upload service. A generated reflection schema preserves actual Go struct JSON typing. The first file and first duplicated form values are retained; the full body is bounded before multipart parsing with Go's file-limit-plus-1MiB envelope. The upload service retains its original enqueue-failure behavior and now exposes an observer for correctly correlated audit task IDs. Production IO error responses use a stable diagnostic rather than expose storage URLs or credentials.

DocumentProcessingHandler performs real storage reads, parser selection, Go-compatible chunking, source locator binding/remapping, actual tenant-scoped embedding model calls, native index writes and durable postprocess enqueue. TXT/MD only receive original-file paragraph locations when reader Markdown bytes equal the original bytes; custom parser rewrites without source blocks do not acquire invented coordinates. CSV uses Go CSV record parsing and original row alignment; CRLF rewrites use SourceAlignment.remapBlocks. Parent text rows are stored but never embedded. Network embedding input uses title + context header + body with Go's base64 cleanup and 20000-rune cap; index content retains the complete unsanitized input apart from invalid UTF/NUL cleanup. Real vectors are checked for count, dimension and finite values before table preparation outside the write transaction.

DocumentProcessingRepository validates task tenant, KB owner, current file identity and reparsing attempt. Chunk deletion/insertion, vector/FTS replacement, quota accounting, parse status and durable postprocess enqueue share one transaction fenced by current job attempt, owner, lease and cancellation. Source and lease are checked again after index callbacks and lease at the end; late invalidation rolls back SQL effects. Quota rows and current knowledge/job rows use PostgreSQL locks where applicable, but PostgreSQL indexing and concurrent PostgreSQL behavior are not verified by these tests. Storage usage applies the new index size minus the prior stored index size to prevent crash/retry double charging, a deliberate improvement over Go's literal addition. Text knowledge remains processing after indexing and becomes completed only through KnowledgePostProcessHandler; empty documents preserve Go's immediate completion and no-op handoff. Raw storage read diagnostics are deliberately replaced by `failed to get file` in public knowledge state; the Go oracle difference is explicit in the test.

Native SQLite indexing requires an operator-selected `WEKNORA_SQLITE_VEC_EXTENSION` (or `weknora.sqlite.vec.extension`) absolute library path compiled at the exact Go-locked sqlite-vec v0.1.6. The repository script `scripts/build-sqlite-vec.sh` reproduces the library. Beans resolve the real extension lazily; missing extension, non-SQLite databases, bound vector-store selection and unsupported native parser/enrichment capabilities fail explicitly rather than publish successful completion. Global bridge startup does not require this library.
