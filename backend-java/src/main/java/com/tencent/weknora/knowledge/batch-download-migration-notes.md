# Native batch original download

`POST /api/v1/knowledge-bases/:id/knowledge/batch-download` invokes Java code with bridge disabled. It uses the Go Contributor workspace floor, Editor KB grant and `retrieve` API-key capability (including the KB allow-list for full-access keys). Every selected document must belong to the effective owner and requested KB before any file is opened. Manual Markdown is exported; non-manual rows without source paths are skipped. Entire requests with missing, deleted, foreign or cross-KB items are rejected.

Admission preserves Go JSON first-value decoding, 64 KiB byte limit, string/rune validation, 1–200 IDs, Unicode whitespace trimming, order and deduplication. A private complete temporary ZIP is built before setting response headers. Four process-wide slots cover creation and serving; every exit removes the temporary archive and releases its slot. Sources stream through a bounded buffer, close after every attempt, and share the cumulative 512 MiB byte limit.

ZIP bytes preserve Go `archive/zip` Store headers/data descriptors, CRC, original ordering, zero modification metadata and UTF-8 flags. File/folder sanitation preserves UTF-8 byte limits, Windows reserved names and case-insensitive collisions. Completed ZIPs use native seekable transport, `application/zip`, attachment and private/no-store headers. POST conditions follow Go ServeContent: If-None-Match `*` returns 412; POST ignores If-Range and still honors Range. Existing GET download/preview behavior remains covered by regression tests.

Evidence sources are `knowledge_batch_download_http_fixture.go` (actual Gin guards, API-key policies, real SQL/share/file services and handler) and `knowledge_download_archive_oracle_test.go` (Go overlay into the production handler package, calling private archive helpers). The HTTP corpus has 127 SQLite cases including 200 distinct files, body/ID boundaries, roles/shares/keys, ZIP bytes, names/folders and conditional requests. PostgreSQL has 125 executable cases from an independent export; 2 NUL text seeds cannot persist in PostgreSQL and are identified, not passed or skipped. Archive helper observations include 20 limit/fault/cancellation cases, including actual 512 MiB and 512 MiB+1 streams. The successful 512 MiB archive digest is compared over the entire Go and Java byte streams. Spring production tests cover real JWT/API keys, resource:// source ownership, manual export, no document/quota/job mutation and rejection before any partial archive. Concurrent tests validate four slots, busy rejection, cleanup after failed response, and reuse.

This route remains **in_progress**. Remaining scope includes automatic Servlet cancellation on client disconnect before the response begins (Go request-context cancellation is not equivalent to Java thread interruption), full legacy/multicloud storage fallback, storage/config/ownership changes while a batch is built, all SQL/filesystem/temp/read/write/response failures and races, tracing, protocols, restart and cutover. The tests do not establish full module or Go replacement parity. Other missing routes and all outstanding queue, transaction/quota, external index and public RAG/agent/module work remain required.

Earlier failures must remain available: the first HTTP differential exposed POST If-Range handling; the first PostgreSQL oracle attempted an impossible NUL text seed and was corrected to classify that database restriction explicitly. Full frozen build and same-jar process evidence, when completed, are recorded separately in the migration checkpoint; focused green tests alone do not prove the entire current source tree.

The first full frozen build (8,603 tests) exposed a pre-existing shared HTTP transport failure: a fast/chunked source overflowed the fixed inbox before the 10 MiB file limit could be returned. Its exit1 report is retained. A real socket regression sends 512 one-byte HTTP chunks in a single write; it fails on the old transport with the same slow-consumer error. The correction bounds socket read batches, preserves every decoded message in the current batch, and pauses future reads at byte/chunk watermarks. A 64 MiB slow-consumer test checks that the producer blocks before body consumption and that every byte/digest arrives after reads resume. This affects the shared model/remote-download client, so transport/model/security and document regressions are rerun; the prior green batch tests and failed full build cannot stand in for the final corrected full source.
