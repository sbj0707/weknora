# Native image:multimodal migration (in progress)

This slice ports the existing Go image worker and the manual-document image producer. It does not establish complete Go feature parity or switch traffic. The Go bridge policy is unchanged.

## Implemented contracts

* Native model-catalog vision resolution accepts the model's stored capability independently of its display `type`, as Go does. The validated dialect is generic OpenAI-compatible vision. Image parts follow the text prompt; the default temperature preserves Go's float32-to-float64 value and truncation/errors are observable.
* The action loop implements caption/OCR switches and observation-driven attributes, including unknown versus negative observations, the conservative OCR policy, business instructions only in the description prompt, scanned-PDF OCR, and child image metadata. Child chunks persist before embedding. Go's swallowed inner indexing failures and retained status-0 children are preserved, rather than falsely reporting an all-or-nothing pipeline.
* Children, physical vector/FTS indexes, statuses, sequence IDs, generation spans and queued postprocess payload/options are compared with real Go service/model HTTP/SQL/Asynq output. Embeddings vary with the actual input; raw float32 bits are checked by child source ID.
* Task/document/KB/parent-chunk binding and freshness are checked before providers and publication. The original unsafe Go 52-case oracle is retained at `/tmp/weknora-go-image-multimodal-before.json`; it showed foreign bindings and changes during Chat could publish children and indexes. The production Go baseline now rejects these bindings and acknowledges superseded source work without draining the successor generation. The Go change also makes image batch ordering explicit using the existing conditional content-byte/source-ID order; ordinary file/chunk contexts are unaffected.
* Manual image resolution saves physical owner resources and binds them before producing image tasks. Supported remote VLM configurations are checked before parent chunk/index publication; legacy constructors retain their closed capability gate. An image generation owns its own fan-in count; summary/question/graph retain their separate document subtask counter.
* Image admissions preserve Go's partial-success behavior: successful siblings survive queue failures, unowned slots are released, and zero accepted images enqueue postprocess with its three-attempt contract. Native SQL uses savepoints to recover from actual PostgreSQL/SQLite statement failures. Accepted image rows and slot state become visible together on commit; Go's Redis/Asynq producer exposes intermediate states and can run siblings before its enqueue loop finishes. This timing difference is explicit and is not covered by claiming the APIs are fully equivalent.
* Per-delivery durable receipts prevent duplicate slot consumption; failed postprocess admission remains retryable without consuming the slot again. These explicit Java task tables require `java-tasks.sql`, or the dedicated `java-image-drains-upgrade.sql` for existing native task installations. No constructor creates schema.
* Postprocess closes a still-running multimodal stage only after owner/source/attempt validation. Skipped/failed stages retain their status. Real public HTTP cancellation and lease/source changes during a VLM response cannot publish children or enqueue postprocess.
* Only malformed `manual:process` and `image:multimodal` JSON is preserved as raw SQL input through task claim. Manual's decoder acknowledges invalid payloads, whereas image's decoder retries. Other corrupt persisted task types retain their previous persistence exception. Three real TaskWorker claim→handler→retry checks verify the image branch.

The scope is actual Go worker66, producer9, raw image queue3, production Spring15, manual public98, manual worker45, resolver57, embedding-pool4 and manual raw queue4. This is a focused candidate, not a shared full-build checkpoint.

Worker66 extends the original 52 with typed ImageActions/SourceLocators errors, float overflow, valid bbox, NULL/empty locator behavior and two foreign legacy-storage-owner cases. The original unsafe resource-owner replay is retained at `/tmp/weknora-go-image-multimodal-before-resource66.json`: an otherwise valid own-document job could read another tenant's legacy local/storage-wrapper URL and publish children. Both Go and Java now reject the owner mismatch before reading bytes or draining the generation counter. The safe actual Go fixture is `src/test/resources/go-image-multimodal.json`; the test does not normalize away provider order, nested JSON strings, physical indexes or source-ID-to-vector raw-bit mappings.

The expanded PostgreSQL replay passed **76 tests / 3 classes**, zero failures/errors/skips: `/tmp/weknora-java-image66-pipeline-postgres-first.log`, with XML under `/var/folders/pf/6ssfy5pj7fj9w1jyg4kpbmcr0000gn/T/weknora-postgres-image-13bvzreo/build/surefire-reports`. That pipeline creates own/shared manual image documents and cancels a third through public HTTP during VLM: 3 documents, 12 jobs, 9 embedding calls, 9 Chat calls and 5 vision HTTP calls, checking physical resources, questions, counters, spans and public index/detail reads.
