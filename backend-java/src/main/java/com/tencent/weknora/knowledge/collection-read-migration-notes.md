# Native document collection reads

`GET /api/v1/knowledge/batch` and `GET /api/v1/knowledge/search` execute Java business logic with bridge disabled. They preserve the original caller while resolving separate execution tenants. Neither endpoint creates jobs or changes documents, quotas, chunks or stored indexes.

Batch binds repeated `ids` (without splitting commas, trimming identifiers, imposing a download limit, or echoing request order). It queries own rows first, then resolves missing identifiers individually through organization KB read permissions, caching each KB permission only within one request. An explicit `kb_id` resolves a KB grant and filters every returned row. An explicit shared agent binds all results to the verified source tenant and its all/selected/empty selection. API-key KB restrictions intersect every result, including full-access keys. It preserves missing/deleted filtering, nullable DTO fields and per-inflight-document last span activity. Tags are not joined: the actual Go batch repository does not load them.

Search accepts `keyword`, then the legacy `query` alias only if keyword is empty. An empty trimmed keyword requires Go's explicit true `recent` values. Pagination defaults to offset 0 / limit 20, with a 100 maximum and Go validation precedence. Own and organization-shared document KB scopes, restricted API-key own-tenant scopes and shared-agent scopes have separate policies. Agent `all` selections apply the Go primary/auxiliary tool capability filter; explicit selections retain Go's distinct behavior. Search counts before limiting, returns the exact has_more flag, joins KB name and both owner/KB identifiers, orders by created_at descending and keeps Go's null-versus-empty behavior. Keyword LIKE metacharacters are escaped; file extensions retain Go's aliases and wildcard semantics. Unicode simple lowercasing follows Go rather than Java's expanding locale lowercase operation.

The actual Go fixture includes production Gin handlers, middleware, SQL repositories, KB/agent/share services, DTOs, tracing reads and denial audits. SQLite TEXT-versus-BLOB config scans and aggregate timestamp representations are retained in exported seeds. PostgreSQL uses an independently executed Go oracle on the complete versioned schema; seeds respect its FK dependency order. Original partial-write Go setup and an exact full SQL-snapshot Go replay are retained separately. A failed comparison exposed background auto-ANALYZE between Go and Java: EXPLAIN showed Go's folder-path index scan with unknown statistics and Java's sequential scan with collected statistics. Because batch has no ORDER BY, this changes array order even for the same rows. The isolated runner pins autovacuum off and exercises unanalysed and explicitly analysed states separately for both runtimes. It compares entire response arrays without sorting, dropping or normalizing their order. These test-only planner controls do not alter production configuration or invent a sort guarantee absent from Go. PostgreSQL timestamp aggregates are converted from JDBC temporal objects directly, and server SQLSTATE diagnostics are rendered in Go's format.

These routes remain `in_progress`. The existing native implementation has no Redis/Wiki housekeeping backlog probe and therefore cannot reproduce a configured Go stall_state verdict. Broader stored-data decoding/fault interleavings, configuration or share changes during a single operation, all clock and Unicode/database collation combinations, restart and complete deployment/cutover behavior have not been fully proven. Presence of these two public reads does not migrate public Agent, chat, Wiki, organization or KB-list functionality. All remaining route/task gaps and existing publication/quota/storage/queue differences still apply.

Current immutable build and differential evidence is recorded in `backend-java/migration/collection-read-checkpoint-2026-10-16.json`. Historical failed comparisons must be retained; a successful subset is not a verified full migration.
