# Native graph query stages

This batch supplies production Spring beans for entity extraction, Neo4j entity search and SQL evidence hydration. `GraphQuerySearch` is an internal stage API. The public session/chat controller, streaming SSE coordinator, complete query-understanding/rewrite/retrieval/rerank/answer pipeline and their route ownership remain outside this batch. The Go hybrid-search HTTP endpoint does not invoke these graph plugins; this batch does not change that endpoint or advertise a native public chat route.

## Production components

- `GraphQueryScope` revalidates the original caller with `KnowledgeBaseReadAuthorization.authorizeChatRead`, the server-loaded KB owner, enabled extraction configuration and server-loaded document rows. Existing `authorizeRead` continues to require `retrieve`; chat-only and retrieve-only API keys retain distinct capabilities. Full-access API keys and KB allowlists use their existing semantics.
- `GraphQueryConfiguration` registers the real model-client and Neo4j-backed stages. Entity-query instructions read the actual `extract.extract_entity` YAML configuration (or the checked-in default resource). Prompt options, rewrite selection and entity parsing follow the production Go plugins.
- `GraphQuerySearch` unions whole-KB and document namespaces, orders namespaces deterministically, keeps the first 30 new graph-referenced IDs before SQL hydration, and distinguishes skipped extraction, successful empty extraction, soft provider/graph/SQL failures and search-nothing results.
- `GraphQueryHydration` rechecks SQL chunk/document owner, KB, document and physical tag binding and enabled/deleted state. A Neo4j reference grants no content access. Image-child expansion binds both levels to persisted parent ownership. Full SearchResult projection retains nulls, metadata, source locators and image info. Deduplication uses existing Go Unicode behavior.
- JDBC text decoding accepts both SQLite TEXT and UTF-8 BLOB. The oracle preserves actual SQLite storage classes, including the BLOB JSON written by Go's repositories. Image-info JSON strings preserve Go typed-struct order, UTF-8-sorted generic map keys, shortest binary64 values, `encoding/json` decimal/scientific thresholds, negative zero and HTML escaping. Tests compare these strings exactly, without reparsing and sorting them.

## Go baseline repairs and real oracle

The original production plugins used raw request KB IDs even when authorized SearchTargets were empty, widened file/tag selection to KB scope, failed to bind all graph/SQL/image-child ownership, and retained permissions revoked during provider calls. Unsafe actual-provider/SQL/Neo4j observations are preserved at `/tmp/weknora-go-graph-rag-grant-audit.json` and `/tmp/weknora-go-graph-rag-before-scope.json` with their logs. These are direct production-plugin observations, not claims that the complete public chat controller was bypassed.

The Go changes add authorized constructor variants, a shared original-caller scope resolver, bound image expansion, fresh grant checks and canonical namespace ordering. `internal/container/container.go` invokes the authorized extraction, standalone search and parallel-search constructors in production; legacy constructor signatures remain available. The parallel constructor also supplies the fresh owner/share resolvers to its unregistered inner entity-search plugin. Shared-agent access is resolved through the actual AgentShareService and KB permission context, not a raw foreign KB lookup. A further internal-stage capability guard rejects retrieve-only API keys while preserving FullAccess. The public Go chat entry already required chat capability. Go image-info merging now sorts URL keys to remove previous map iteration instability; this is a production baseline repair, not test-side result sorting.

`src/test/fixtures/graph_query_fixture.go` runs production event-manager plugins registered through the same authorized constructor functions, real repositories/schema migrations, actual model HTTP requests and actual Neo4j/APOC. Its final 55 cases cover own/shared/agent grants, file/KB/tag restrictions, empty/foreign selections, corrupted metadata, NULL/empty results, the 30-candidate cap, Unicode deduplication, child/grandchild image binding, source locators, query intent/rewrite, provider/parse errors, disabled features, mid-provider share/owner/config changes, API capabilities/allowlists, SQLite BLOB storage and image attributes with difficult numeric JSON.
