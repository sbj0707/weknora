# Native summary:generation migration — in progress

## Production behavior now available

`SummaryGenerationHandler` implements the actual Go `TypeSummaryGeneration` name,
`summary:generation`, without Go HTTP forwarding. It is registered by the opt-in
`SummaryGenerationConfiguration` when `weknora.knowledge.processing.enabled=true`.
Production document parsing now permits this enrichment, and native postprocess
creates a durable summary job in the `summary` queue with three retries and a
30-minute deadline. Existing constructors keep their previous default behavior;
only the production factory enables the new handler.

The new repository writes the existing Go knowledge/chunk/index tables. The
receipt schema is explicit in migration/sql/java-tasks.sql; existing isolated
Java task databases apply java-summary-drains-upgrade.sql. Constructors perform
no DDL; sql.init remains disabled. It checks
payload versus job tenant, document versus KB owner, deleted rows, task lease,
processing attempt, custom metadata bytes, chunk revision and enabled state.
Summary fields do not overwrite parse status. A malformed cross-owner/KB binding
cannot decrement another document's counter, even on the final delivery.

The worker preserves these Go checkpoints:

1. Mark summary processing while retaining an old description/profile.
2. Reconstruct the text: immutable source overlap versus edited chunk order,
   enabled image children/captions/OCR, rune-based sampling, minimum substantive
   content and stable custom metadata. Filename/title are excluded from the chat
   request. The original default document-profile prompt and model options are
   covered by a real Go HTTP sample.
3. Save description/profile/summary_status before creating a summary chunk.
4. Commit a new summary chunk before embedding/index resolution. An index failure
   leaves this already saved summary and chunk visible, as Go does. Initial
   generation uses summary content alone; refresh prepends the document title to
   retrieval/embedding content through Go's updateChunkVector behavior.
5. Embedding retries five times with the same 200 ms exponential backoff as Go.
6. On retryable chat/model failure keep the old summary and set pending. On the
   final failed delivery use the first ordered text chunk, capped to 500 runes,
   clear the profile, mark the summary failed and release its enrichment slot.
   Insufficient content and no-model/no-text exits are terminal without inventing
   a successful result.

`refresh=true` updates every existing summary chunk in place and enables it;
creates one if absent; deletes the old chunk indices before reindexing; preserves
parse/pending-counter fields; does not release a parent enrichment slot. Current
public edit/regeneration HTTP routes that would enqueue refresh are not introduced
by this batch. Task payloads can already execute the native refresh behavior.

Go's initial summary max chunk index is derived from its text-only
ListChunksByKnowledgeID result, not from image/table/summary chunks. The native
implementation matches that behavior. The normal finalizer releases only terminal
work, not a retry or an obsolete attempt, and preserves cancelled/deleting parse
status. Native finalizer receipts (`java_summary_task_drains`) prevent a replayed
job from draining twice; the receipt and decrement/promote commit together.

Summary records use `postprocess.summary` under the existing postprocess stage.
The root is already closed by postprocess dispatch, as in Go; a later summary
failure does not rewrite the completed parse root as failed. Existing spans,
stages, document fields and chunk-details reads display actual native artifacts.

## Verification evidence

The checked-in generator is `src/test/fixtures/summary_generation_fixture.go`.
It invokes production Go ProcessSummaryGeneration/RegenerateKnowledgeSummary,
production GORM repositories, the SQLite retrieval engine and actual local HTTP
model endpoints. Its 44 scenarios are saved in
`src/test/resources/go-summary-generation.json`.

`SummaryGenerationGoParityTest` strictly compares all 44 samples against actual
provider HTTP JSON and committed Go SQL projections after the Go cancellation
fix described below. This includes plain/profile/fenced/
wrapped/invalid/null JSON, Unicode profile truncation/topic deduplication,
metadata, edited/overlapping/disabled/image-ocr chunks, long/small sampling,
empty/provider/model errors on retry/final delivery, chunk/index write errors,
content/metadata staleness, no model/text, cancelled/deleting state, refresh and
multiple existing summaries, and graph-only/wiki-only strategies without vector
or keyword indexing. Numeric JSON wrapper types are normalized mathematically;
UUIDs generated by the worker are labeled `new-summary`. Field presence, null,
HTTP message content, index data, persistence checkpoints and errors' retry
versus acknowledgement decision are retained. Raw dependency exception wording
is not asserted to be identical: native durable task failures use operator-safe
messages, while the private exception is recorded in the processing span detail.

Six `SummaryGenerationPipelineHttpIntegrationTest` cases exercise fresh shared-KB
multipart uploads through actual Spring production beans, real local chat/
embedding HTTP, durable jobs, physical SQLite retrieval rows and spans/stages/
chunk-details HTTP. They cover owner tenant versus shared upload actor, foreign
reader rejection, expected summary queue/deadline/retry budget, normalized profile,
retry/final fallback accounting, superseded attempt, lost lease during model I/O,
malicious final-delivery tenant/KB binding, repeated terminal delivery receipt,
and rollback when durable summary enqueue fails. Two schema tests prove construction creates no table and the explicit upgrade
is idempotent without deleting a receipt. The 11 existing native pipeline
trace scenarios also pass after enabling summary. Their fixture explicitly
bootstraps the native database runtime before opening SQLite, matching production
main's loading order; this is required on the tested macOS arm64 runtime.

## Explicit differences and remaining work

- The original real Go `cancel-during-chat` fixture exposed a cancellation bug:
  Go published description/profile/chunks/indexes after cancellation during Chat.
  `summarySourceChanged` now treats cancelled/deleting documents as stale after
  model I/O. The actual Go fixture was regenerated, and all 44 cases now compare
  strictly. Java acknowledges obsolete business-cancelled work while retaining
  lease, task cancellation and interruption failures. The original unsafe fixture
  is retained at `/tmp/weknora-go-summary-generation-before-cancel-fix.json`.
  The four-class focused suite passed again: 63 tests, zero failures/errors/skips,
  `/tmp/weknora-java-summary-cancel-alignment.log`. Earlier packaged/full-suite
  results predate this fix; a fresh packaged verification is still required.
- Native postprocess summary handoff is an owner/source/attempt/lease-fenced
  atomic state/counter/enqueue transaction. Go promotes finalizing and enqueues
  separately, then reconciles unowned slots. The native atomic handoff avoids
  stranding an un-enqueued slot; its rollback is tested. Go partial enqueue
  failure side effects are not claimed identical.
- Root/document chunk publication remains the previously documented atomic
  Java pipeline, while Go persists chunking before embedding. This summary
  batch does not change that timing. Root separately fixed initial document
  processing to preserve `table_summary`/`table_column`; Go reparse already
  performs synchronous old-content cleanup before its queued document worker.
- Native finalizer receipts improve duplicate terminal delivery accounting.
  The exact Go crash-between-handler-return-and-queue-ack window has not been
  reproduced against a live Asynq executor. Detached terminal SQL accounting is
  owner/attempt/lease fenced; there is no equivalent full native housekeeping
  sweep in this batch.
- Go's best-effort knowledge-base profile refresh, audit/model usage aggregates,
  Langfuse LLM emission and all optional question/graph/wiki/tag enrichments are
  not implemented by the summary handler. A KB with an enabled unmigrated
  enrichment is still rejected by the existing guard; it is not quietly ignored.
- The shipped prompt is a snapshot of config/prompt_templates/generate_summary.yaml.
  Native overrides are weknora.knowledge.summary.prompt, .max-input-chars and
  .max-tokens. Automatic loading of arbitrary Go conversation YAML/template
  overrides is not implemented. Locale fallback uses WEKNORA_LANGUAGE then
  zh-CN. JSON typed output casing/duplicate-field edge cases and unusual custom
  metadata float formatting beyond the committed oracle need further fixtures.
- External/vector-store bound KBs remain explicitly unavailable through the
  existing index resolver. PostgreSQL native success-path summary/profile/halfvec publication is verified in the isolated full-schema integration above; summary-specific PostgreSQL Go differential and failure paths remain pending. Multiworker shutdown/restart and all
  original API entrypoints are not claimed covered by this focused batch.
- SQLite summary chunk seq_id is allocated atomically inside INSERT from the
  global maximum, including deleted/foreign history, matching Go
  AssignChunkSeqIDs. All 44 oracle projections compare seq_id, and the plain
  case proves a deleted foreign row at 10000 yields new summary seq_id 10001.
  Refresh keeps existing sequence IDs. PostgreSQL continues using its existing
  schema sequence. Whole document-processing sequence allocation is owned by
  the document repository migration and is not claimed verified by this batch.

The overall migration remains in progress. These tests establish the specific
summary branches listed above, not complete Go functionality parity.
