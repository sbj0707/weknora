# Native document image update

`PUT /api/v1/knowledge/image/:id/:chunk_id` is registered when native document processing is enabled. The API key ingest gate, creator-or-Admin ownership, shared Editor grant, original caller identity and KB allow-list run before JSON binding. The image payload is a JSON string: Gin binds its first outer value, whereas the service decodes the entire inner array using the current Go ImageInfo/ImageAttrs types. Arrays whose length differs from one return success before chunk lookup. A null image pointer preserves Go Recovery's explicit 500 response.

The service validates parent and every child document binding before writes. It compares the first stored image URL and only updates OCR/caption children whose corresponding text changed. Missing nonempty caption/OCR children are created enabled, with Go zero/default fields and database-specific seq_id allocation. CreateChunks is one transaction; parent and changed children commit individually; retrieval deletion and replacement follow these commits; the final document hash is MD5(document ID + previous hash + sanitized raw image_info). A failed hash save is best effort. Child/parent/index failures retain the same earlier SQL commits. No chunk revision, summary refresh, quota adjustment, processing task or new audit event is invented.

Index content includes the document title, context header and generated question aliases. Source deduplication keeps the first occurrence; Go's map iteration does not define batch entry order. SQL metadata, raw image strings, changed timestamps, phase order and all error DTOs are compared independently from that unordered batch. A retry with unchanged child text only reindexes the parent, matching the current Go service even when a previous index failure left the child absent from retrieval.

The source oracle uses production Go middleware, handler, service and SQL repositories with a controlled retrieval boundary. Production Spring tests separately exercise JWT, API keys, sharing/revocation, a real embedding HTTP server and physical sqlite-vec/FTS. The PostgreSQL runner creates an owned loopback database, applies all production migrations, exports an independent Go corpus and replays it through Java with Hikari pool size one. Its independent chunks_seq_id_seq sequence is explicitly reset by the seed; pg_get_serial_sequence is NULL because the migration's manually created sequence is not owned by the column.

This route remains in_progress. The existing native Indexes resolver supports SQLite/PostgreSQL document indexes and explicitly rejects a bound external vector store. Full environment-selected composite engine behavior, arbitrary stored JSON/type/size/Unicode boundaries, concurrent authorization/source changes and complete migration/cutover remain outstanding. A route mapping and bounded differential corpus do not prove full Go parity. See the current migration comparison and image update checkpoint for validation evidence and the exact source/jar covered.
