# Original document download and preview

Native GET endpoints: `/api/v1/knowledge/{id}/download` and `/api/v1/knowledge/{id}/preview`.

Downloading requires the workspace Contributor floor plus an Editor KB grant; it does not require the caller to have created the KB. Preview requires Viewer access and retains the read authorization's organization/agent fallback. Machine credentials require `retrieve` or full access and remain restricted by their KB allowlist. Raw route IDs and sanitized handler IDs each require their own KB grant and API-key allowlist, including full-access keys with a restricted KB list. The original authenticated caller is retained for denied-role audits; the resolved KB owner supplies storage access. Bridge forwarding is not counted as native execution.

Manual documents stream decoded `ManualKnowledgeMetadata.content` as Markdown, with Go's title sanitization and `.md` suffix. Empty/NULL metadata returns an empty file. The typed Go JSON decoder checks all five metadata fields, including invalid numbers, duplicate/null fields and case folding. Original physical files retain local seeking through resource and storage-backend wrappers.

The transport implements the production Go safe extension table, forced attachment for active browser content, MIME filename escaping/RFC2231, no-store/nosniff, octet-stream downloads, byte ranges, multipart ranges, range errors and the handlers' unknown-ETag/unknown-modification-time preconditions. Streaming readers, including manual Markdown, ignore range/conditional headers and advertise `Accept-Ranges: none`, as Go does. Spring's implicit HEAD mapping is explicitly rejected because the Go router only registers GET. Every response path closes its reader, without loading a physical file into memory to implement seeking.

Evidence for this checkpoint:

- `knowledge_file_http_fixture.go` invokes actual Gin middleware, knowledge repositories/services, local file service and filetransport. SQLite exports 209 observations; PostgreSQL independently exports the same scenes, with 207 executable cases. The two malformed JSON values cannot be stored in PostgreSQL's jsonb column and are explicitly identified in its export, rather than reported as passed.
- `KnowledgeFileGoHttpParityTest` compares all file bytes, range/multipart bodies, response headers, errors, denial audits, unchanged documents/quota and absence of new tasks. Only generated multipart boundary entropy and isolated filesystem base paths are normalized; JSON errors compare parsed fields and equivalent UTF-8 JSON media types.
- `KnowledgeReparsePipelineHttpIntegrationTest` adds four tests through production JWT/API-key filters, real uploads/resource catalog and HTTP controllers: owner/shared access, noncreator Contributor downloads, Viewer preview/download distinction, API scope/KB restrictions, ranges/conditional headers/HEAD, manual Markdown and active content.
- `FileTransportTomcatHttpIntegrationTest` exercises real HTTP connections: Tomcat ignores `setHeader(name, null)`, so error/304 header removal resets and restores the retained headers before writing any body. The first packaged run exposed this difference despite MockMvc passing; that failure is preserved.
- `postgres-file-parity.py` owns a loopback PostgreSQL instance, applies all versioned Go migrations plus the native SQL queue schema, runs an independent Go export and uses a Hikari pool of one for Java replay. It stops only its owned container.
- `processing_smoke.py --file-response` verifies original uploaded resources through an isolated packaged Java process, including owner/shared reads, exact bytes, ranges, conditional responses and share/workspace role changes, retaining document/quota/job state.

Status remains **in_progress**, not verified. Full build and packaged evidence must be read from the checkpoint manifest; focused parity tests alone do not prove the entire migration complete.
