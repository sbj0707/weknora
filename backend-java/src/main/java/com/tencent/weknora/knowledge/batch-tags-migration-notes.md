# Native batch document tags

`PUT /api/v1/knowledge/tags` uses the Go Contributor floor, ingest API-key capability, original-caller KB allow-list, editor KB write grant and the handler's subsequent creator/Admin check. An explicit `kb_id` is sanitized before resolution; otherwise Go infers a KB from an unspecified entry of the updates map. Java also leaves that entry unspecified; mixed-KB/missing-ID requests without an explicit KB have no stable error-precedence contract. Go map selection probabilities are not an API guarantee. No cross-KB write grant is invented.

Binding preserves the first JSON value, case-insensitive struct fields (including Go simple folding), duplicate updates-map merging, duplicate map-key replacement, null map reset, null/string slice elements, UTF-8/surrogate behavior and Gin required/min errors. IDs and tag IDs are not trimmed, split or translated from seq IDs.

All resource IDs are checked in Go UTF-8 string order before writes: missing/deleted/foreign documents, unfinished moves, persisted parent ownership and the single authorized KB grant. All nonempty tag IDs are checked against the execution owner and each document's KB. Only after validation does the repository replace relations. Each document has its own transaction, with a single multi-row insert preserving tag order while dropping duplicate/empty IDs. A failing replacement rolls back that document's delete and insert; earlier documents remain committed. There is intentionally no transaction wrapping the whole batch. Clearing or reapplying the same tag also replaces relation creation timestamps, and does not update document timestamps, content, indexes, quota or jobs. No mutation activity audit is invented; role-denial audits keep the original actor.

Actual Go fixtures execute production Gin handlers, API-key/RBAC middleware, service access and SQL repositories. The SQLite corpus contains 96 scenes; the independently executed PostgreSQL corpus has 95 persistable scenes after all 115 Go migrations, with one malformed JSON seed explicitly classified as nonpersistable. Tests compare entire HTTP status/body, relation identities and replacement-time markers, partial commits/rollback, denial audits, and unchanged document/KB/tag/tenant/task state. Production Spring/JWT/API-key/shared-owner flows also retain actual processed indexes and quota.

This route remains `in_progress`: unspecified mixed-input error selection, all stored-data typed decoding, grants/configuration changing during admission or per-document commits, concurrent writes/deletes, driver isolation/collations/clocks, cancellation/restart/cutover and the remaining modules need broader verification. An entry and bounded differential coverage do not prove the complete migration. Immutable build, package and differential evidence belongs in `backend-java/migration/batch-tags-checkpoint-2026-10-16.json`; prior collection-read evidence remains historical after these source changes.
