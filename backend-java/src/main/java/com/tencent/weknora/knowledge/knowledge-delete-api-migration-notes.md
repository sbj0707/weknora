# Public document delete admission

Native DELETE `/api/v1/knowledge/{id}`, POST `/api/v1/knowledge/batch-delete` and DELETE `/api/v1/knowledge-bases/{id}/knowledge` are implemented under the existing processing switch. The completed slice is included in the immutable 6,511-test/135-class jar. Bridge ownership remains unchanged. The public response means admission to native `knowledge:list_delete`, not completed deletion; clear retains Go's response without a task ID.

The formal `knowledge_delete_http_fixture.go` executes actual Go handlers, knowledge/KB services, SQL repositories, role/ownership/KB/API capability middleware and Redis-backed Asynq producer. Its 123 scenes compare full HTTP envelopes, unchanged persisted document bindings and admitted payload/ordered IDs/initiator/low queue/four attempts/two-hour timeout. Only the generated public task UUID is validated and normalized; the native response is separately checked against its actual persisted task ID. Go fixture authentication identity is injected, so those scenes do not claim Go JWT authentication.

Single delete permits the current own-KB creator, including Viewer, or Admin, then requires KB Editor access. Batch requires a Contributor floor, decodes Go's first JSON value and typed required string/slice, trims/deduplicates IDs in caller order, enforces 200 unique IDs, resolves Editor access before creator-or-Admin ownership, and checks every current document belongs to the admitted owner/KB. Clear requires Admin or a full-access API key and a current owned-KB Admin grant; shared Editor cannot clear. Empty clear admits no task. Full-access API keys remain restricted by a populated KB allow-list.

KB IDs from the batch body retain their original bytes for lookup; sanitizing them could incorrectly turn a control-containing identifier into an existing KB. API-key allow-list lookup trims Go whitespace as Go `TenantAPIKeyScope.AllowsKnowledgeBase` does, while SQL still receives the original identifier. The real PostgreSQL oracle exposed a further difference: a NUL-containing ID produces SQLSTATE22021 and Go HTTP500; the native batch path now maps that specific actual SQLSTATE to the same fixed error message. It does not copy arbitrary driver diagnostics.

The shared `KnowledgeTransferState` helper reads exact outer map keys, retains the last raw transfer object, then applies typed Go struct decoding with duplicate/null/folded-field behavior. Moving requires both `operation=move` and `phase=moving`. Copy, phase-only and outer-map case variants do not block deletion. The previous worker's phase-only check was too broad. The formal worker fixture now has 46 actual Go scenes, including ten transfer metadata cases; native replay has one additional lease/binding guard. Malformed metadata retains Go retry-vs-terminal behavior. PostgreSQL JSONB normalizes persisted duplicate keys; PG comparison uses the actual separately executed Go/PG oracle, without assuming SQLite byte storage behavior.
