# Native SQL queue and Go worker topology

The Java worker consumes only the explicit Java SQL queue. It does not read Redis or consume Asynq jobs. Automatic schema changes are disabled. Create a new isolated queue with `migration/sql/java-tasks.sql`; upgrade an older Java queue with `migration/sql/java-tasks-options-upgrade.sql` instead.

`weknora.tasks.enabled=true` enables workers. The default topology is `single`, preserving the existing bounded worker. Set `weknora.tasks.topology=go` to reserve independent core, postprocess, enrichment, maintenance, shared and wiki capacities (defaults 8, 2, 12, 4, 6, 8). These six executors share the durable repository and fence each claimed attempt, while their capacity remains independent. The shared executor consumes only core and enrichment queues; maintenance, postprocess and wiki are excluded. Queue weights and all 22 task type mappings match the current production Go registry.

At startup the six capacities use the actual Go system-setting keys and ENV names. Valid edited DB integers override ENV, unchanged bootstrap default rows fall through to ENV, malformed/unavailable DB values fall through, and zero/negative resolved capacities use the Go per-pool defaults. This is a startup snapshot; Java has not migrated the runtime system-setting/task-management APIs. Java explicitly bounds each executor to 1..64 to retain its existing resource limit; positive Go settings above that range are not silently accepted.

`TaskTopologyGoParityTest` contains five JUnit methods: production registry comparison, 294 production GetInt/ResolveWorkerPoolConcurrency cases, real SQLite saturation proving reserved parsing/postprocess capacity, Spring opt-in bean lifecycle, and validation before claims. The fixtures are generated by the actual Go services and registry:

```sh
go run backend-java/src/test/fixtures/task_topology_fixture.go
```

Task producer options preserve queue and timeout. MaxRetry(3) is four total attempts. Producer calls get fresh IDs and join the caller transaction; explicit business idempotency keys retain tenant/type/key deduplication. The retry formula matches the locked Asynq default formula, but special wiki retry delay, task administration, Redis migration and the full set of business handlers remain separate work. SQL delivery is at least once; external side effects require their own idempotency and compensation.
